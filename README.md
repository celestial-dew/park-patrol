## 📜 项目简介

随着城市化进程加速，机动车违停问题严重占用道路资源并威胁公共安全。传统人工巡查存在效率低、盲区大、无法全天候覆盖等痛点。本项目是一套基于深度学习的端到端机动车违停抓拍与边缘 AI 管理系统，旨在通过 **计算机视觉技术** 实现自动化、智能化、持久化的交通巡检。

系统支持无缝接入固定监控网络或无人机视频流，采用前沿的轻量级目标检测与多目标追踪算法，结合“生产者 - 消费者” **多进程架构**，可在 Jetson Nano 等资源受限的边缘计算设备上实现低延迟、高精度的实时违停判定与车牌识别，为智慧城市建设提供低成本、易部署的 AI 解决方案。

## 📦 主要特性

### 轻量与精度平衡

采用原生端到端 **YOLO26** 目标检测模型（122个卷积层，约 9.46M 参数，20.5 GFLOPs），单帧推理仅需 **3.9ms**，在边缘设备上可达 25 FPS 的实时检测帧率。

### 抗遮挡追踪

集成 **BoT-SORT** 算法，融合 128 维外观特征与 6 维运动特征，结合 **卡尔曼滤波** 与 **匈牙利算法**，大幅降低树木/车辆遮挡及摄像头抖动场景下的 ID 切换率（ID Switch）。

### 多进程架构

创新运用“生产者-消费者”模型，将计算密集型（GPU 推理）与 IO 密集型（UI 渲染/存储）物理隔离，显著缓解传统单线程架构导致的 UI 卡顿与掉帧问题。

### 泛化训练策略

摒弃易过拟合的自适应优化器，采用 SGD + 动量 + 权重衰减的方案，配合基于 70% 分位数的动态 `imgsz` 适配，显著提升雨夜、逆光等复杂长尾场景的泛化能力。

### 全链路自动化闭环

深度集成 **HyperLPR3** 车牌识别引擎，自动完成车辆检测 $`\to`$ 轨迹追踪 $`\to`$ 停留判定 $`\to`$ 车牌抓拍 $`\to`$ 违停告警的全链路闭环。

### 开箱即用的便捷

基于 PyQt5 打造 UI 界面，提供模型训练、多源视频接入、参数动态调优及红/黄/绿三色状态实时面板，内置自动化依赖管理逻辑，实现真正的“开箱即用”。

## 🔁 系统运行流程

系统采用“生产者 - 消费者”多进程设计，将计算任务与渲染存储任务分离：

### 生产者进程

- 读取摄像头、本地视频或网络视频流。
- 使用 YOLO26 进行车辆检测。
- 使用 BoT-SORT 进行多目标追踪。
- 调用 HyperLPR3 完成车牌识别。
- 根据停留时间与位移变化判断违停状态。

### 消费者进程

- 接收生产者进程输出的结构化结果。
- 在 PyQt5 界面中实时渲染检测框和状态。
- 记录运行日志。
- 将检测结果编码保存为本地视频。
- 可扩展为 HTTP/HTTPS 上报接口。

该架构有助于降低 UI 阻塞风险，使检测、显示和保存任务能够相对独立地运行。

## 🚀 快速开始
```bash
git clone https://github.com/celestial-dew/park-patrol.git
cd park-patrol
```
平台要求 [Python](https://www.python.org/downloads) 3.10 以上。（推荐用虚拟环境）运行时导入 `model` 能自动检测并配置 `torch`、`ultralytics`、`hyperlpr3`、`PyQt5` 等必需依赖，无需用户手动配置。

但要手动下载思源黑体 [SourceHanSansSC-VF.ttf](https://github.com/adobe-fonts/source-han-sans/raw/release/Variable/TTF/SourceHanSansSC-VF.ttf) 至 `park-patrol` 目录，再运行：
```bash
python main.py
```
### 模型训练

在 UI 左侧 `模型训练` 面板中：

- 选择准备好的数据集配置文件（如 `vehicle.yaml`）。
- 设置 `Epochs` (训练轮数) 与 `Batch Size` (批大小)。
- 点击“开始训练”，日志将实时重定向输出至界面文本框。
- 训练结束后，最优权重将自动保存至 `result` 目录并热加载至系统。

`vehicle.yaml` 内容如下：
```yaml
path: dataset/vehicle
train: train/images
val: valid/images
names:
  0: bus
  1: car
  2: truck
  3: taxi
```
系统也允许用户自定义数据集，先修改 `yaml` 数据集配置文件的 `names` 属性内容，再用 [labelImg](https://pypi.org/project/labelImg) 输出 YOLO 格式标签至对应的 `labels` 目录，注意各类别首次出现顺序必须与 `names` 定义的顺序相同。

### 违停检测

在 UI 左侧 `检测控制` 面板中：
- 输入摄像头编号（如 `0`）、网络视频流或选择本地视频文件。
- 配置停留秒数（默认 5.0 s）、归一化位移阈值（判断车辆是否有效移动，数值越小越敏感，默认 0.003）等核心参数。
- 点击“开始检测”，右侧画面将实时渲染检测框与车牌信息。
- 观察信息列表：
  - 🔴 **红色 (Illegal)**：违停，已触发告警。
  - 🟡 **黄色 (Warning)**：停靠中，正在计时。
  - 🟢 **绿色 (Normal)**：正常行驶。

## 🧮 核心算法

### 鲁棒的训练策略

突破传统 Adam 优化器在复杂场景下易过拟合的缺陷，采用带有动量 ($`\gamma`$) 和权重衰减 ($`\lambda`$) 的 SGD：

$$
\begin{cases}
v_{t+1} = \gamma \cdot v_t + \eta \cdot (\nabla J(\theta_t; x^{(i)}, y^{(i)}) + \lambda \cdot \theta_t) \\
\theta_{t+1} = \theta_t - v_{t+1}
\end{cases}
$$

同时，针对数据集聚焦不一的问题，创新采用 **70% 分位数** 动态计算输入图像的标准大小（`imgsz`），避免极端尺寸拉扯失真，下界设为 704 以保留小目标特征：

$$
imgsz = \max(704, percentile(imgszlist, 70))
$$

[示例数据集](https://github.com/celestial-dew/park-patrol/releases/download/dataset/dataset.zip) 的 `vehicle` 包含 1236 张车辆图像，覆盖晴天、雨天、夜间、逆光、遮挡等多种复杂场景，并针对车辆位置、车辆类型等关键信息进行标注。其训练的模型在验证集的表现如下：

| class | images | instances | precision | recall | mAP50 | mAP50-95 |
| --- | --- | --- | --- | --- | --- | --- |
| all | 75 | 199 | 89.2% | 80.9% | 89.3% | 69.6% |
| bus | 8 | 10 | 91.3% | 100% | 99.5% | 84.3% |
| car | 51 | 119 | 85.5% | 88.2% | 91.0% | 68.3% |
| truck | 24 | 49 | 84.2% | 54.6% | 71.7% | 51.2% |
| taxi | 10 | 21 | 95.9% | 81.0% | 94.9% | 74.5% |

### 追踪机制优化

构建“检测-特征提取-状态预测-数据关联”的闭环流程。通过加权融合的代价矩阵与匈牙利算法，实现目标 ID 的稳定匹配：

$$
C_{m,n} = \alpha \cdot (1 - \cos(f^{app}_{t,m}, f^{app}_{t-1,n})) + (1 - \alpha) \cdot IoU(b_{t,m}, \hat{b}_{t,n})
$$

结合 **卡尔曼滤波** 预测车辆运动状态，使系统在摄像头细微移动或无人机抖动场景下的误判率显著降低。

## 🧪 测试与部署

系统支持在 Windows 与 Linux 环境下运行，并可在边缘计算设备上进行部署。由于边缘设备算力有限，建议在实际部署前确认以下事项：

- 是否具备可用的 GPU/NPU 或足够 CPU 性能。
- 视频分辨率是否与设备算力匹配。
- 是否同时运行检测、追踪、车牌识别和界面渲染。
- 存储设备是否支持持续写入。
- 网络视频流是否存在延迟或丢帧。

在普通场景测试中，白天光照条件较好时检测稳定性较高；夜间、逆光、雨夜等复杂场景下，识别准确率和追踪稳定性可能出现一定程度下降。因此，实际部署时建议根据场景调整置信度阈值、停留时间阈值和位移阈值。

## ⚠️ 已知限制

- 极端天气场景，如大雾、暴雨、强反光等，仍需更多数据验证。
- 夜间低照度场景下车牌识别准确率可能下降。
- 在低功耗边缘设备上同时运行检测、追踪、识别和 UI 渲染时，资源占用较高。
- 高分辨率视频流可能导致边缘设备帧率下降。
- 真实无人机图传延迟、空中抖动和长时间空巡联动仍需进一步验证。
- 系统输出适合作为辅助监测手段，不建议直接作为最终执法依据。

## 🎯 应用场景

- **城市智慧交管**：无缝对接城市道路的交通监控探头，实现持久化自动化巡检，释放警力资源，精准打击主干道及消防通道违停行为。
- **无人机空巡**：支持接入无人机 RTMP/RTSP 视频流。利用无人机的高机动性，快速覆盖偏僻街道、小巷及临时停车区域，有效解决固定监控的视觉盲区与树木遮挡问题。
- **封闭区域管理**：针对内部道路、停车场及应急通道，提供低成本的边缘 AI 盒子部署方案。系统自动记录违停车辆并生成结构化日志，辅助物业或安保进行精细化治理。

## ❓ 常见问题

### 启动后界面中文显示异常

请确认已下载 `SourceHanSansSC-VF.ttf`，并将其放置在项目根目录。

### 首次运行很慢

首次运行时会自动检测并安装部分依赖，如 `PyTorch`、`Ultralytics`、`HyperLPR3`、`PyQt5` 等。后续启动速度会明显提升。

### 无法打开摄像头

请检查摄像头编号是否正确。例如本地摄像头通常可以尝试 `0` 或 `1`。如果使用的是网络摄像头，请确认 RTSP/RTMP 地址可访问。

### 边缘设备帧率较低

可以尝试：

- 降低输入视频分辨率。
- 关闭不必要的界面渲染。
- 减少同时运行的识别任务。
- 使用 GPU/NPU 加速。
- 降低视频源帧率。

### 训练日志没有输出

请确认数据集配置文件路径正确，并检查 `vehicle.yaml` 中的 `path`、`train`、`val`、`names` 等内容是否与实际目录一致。
